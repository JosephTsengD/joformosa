## 問題

台灣使用者的登入轉換率，LINE 遠高於其他方式。但 Supabase Auth 沒有內建
LINE provider，而 LINE 的 token 交換需要 channel secret。

## 硬性約束

**channel secret 絕對不可進入前端。** 任何進到 JS bundle 或 App bundle
的密鑰都是公開的。交換必須在 Edge Function 執行。見 `docs/adr/007`。

## 驗收條件

Scenario: PkceChallenge
  Given 一組 code_verifier
  When  產生 code_challenge
  Then  結果為 base64url(sha256(verifier)) 且不含 padding
  And   challenge 不等於 verifier（不是純文字 PKCE）
  And   授權網址標示 code_challenge_method=S256

Scenario: StateVerification
  Given 一次已啟動的登入流程
  When  callback 的 state 與發出時不符
  Then  拒絕該次登入並清除待處理狀態
  And   相同的 callback 不能被重放第二次

Scenario: CallbackErrors
  Given LINE 導回帶有 error 參數
  When  處理 callback
  Then  「使用者取消」與「provider 錯誤」可被區分
  And   沒有待處理流程時，收到的 code 一律拒絕

## 不做什麼
- 不要 email scope（需事前送審，且本專案不需要 email）
- 不做 LINE Messaging API 推播
- 行動裝置的 OAuth 流程另立 T-086（web 先上）
