## 問題

目前只能靠篩選逐層縮小。但使用者心裡多半已經有目標
（「大安區有沒有跑團」「HYROX 台中」），篩選回答不了這種問題。

## 契約

沿用既有的 `CrewFilter.query`，不新增 repository 方法。
後端改用 `websearch_to_tsquery` 並加上 pg_trgm 模糊比對，
處理中文斷詞與錯字。

## 驗收條件

Scenario: SearchDebounce
  Given 使用者在搜尋框連續輸入「大安森林」
  When  每個字元間隔小於 300ms
  Then  只發出一次查詢
  And   輸入過程中舊的回應被丟棄，不會覆蓋新結果

Scenario: SearchEmptyState
  Given 搜尋「不存在的社團名稱」
  When  結果為空
  Then  顯示空狀態並提供「清除搜尋」
  And   **不**顯示與篩選無關的通用文案

Scenario: RecentSearches
  Given 使用者曾搜尋過三個關鍵字
  When  再次聚焦搜尋框且輸入為空
  Then  顯示最近三筆，最新在最前
  And   重複的關鍵字只保留一筆（不是兩筆）
  And   上限 8 筆，超過時移除最舊的

Scenario: SearchUrlSync
  Given 使用者搜尋「夜跑」並分享網址
  When  另一人開啟該網址
  Then  搜尋框已填入「夜跑」且結果相同

## 不做什麼
- 不做搜尋建議 / 自動完成（T-084）
- 不做搜尋結果的關鍵字高亮（視覺雜訊大於收益）
- 不做語音搜尋
