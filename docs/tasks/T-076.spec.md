## 問題

`submit_crew()` 寫入 `status='pending'`，但**沒有任何介面可以把它改成
published**。使用者送出後石沉大海，比不開放送出更糟。

這是 `docs/PRODUCTION.md` 的 P0 項目，**開放真實使用者的硬前提**。

## 技術決定

管理員身分用 `auth.users.raw_app_meta_data->>'role' = 'admin'` 判定，
**不是**在 `crews` 表加欄位——角色屬於使用者，不屬於資料。

RLS 加 admin 政策；審核動作走 RPC 以便寫入稽核紀錄。

## 驗收條件

Scenario: AdminOnlyAccess
  Given 一般使用者（含匿名）
  When  以任何方式存取審核 API
  Then  被 RLS 拒絕
  And   前端路由也不可達（不能只靠隱藏按鈕）

Scenario: ApproveFlow
  Given 一筆 pending 的社團
  When  管理員按下核准
  Then  status 變為 published 且立即出現在公開列表
  And   寫入一筆稽核紀錄（誰、何時、什麼動作）

Scenario: RejectWithReason
  Given 管理員拒絕一筆送出
  When  必須填寫理由
  Then  理由為空時不可送出
  And   status 變為 archived 且理由被保存

Scenario: ModerationAudit
  Given 任何審核動作
  When  查詢稽核表
  Then  能還原完整的狀態變更歷史
  And   稽核紀錄不可被修改或刪除（只增不改）

## 不做什麼
- 不做自動審核 / AI 內容判定
- 不做多層審核流程
- 不做審核者績效統計
